这次历史重构更改 SDK、CLI、项目编写的 Skill 和生成内核的项目名称，当时保留 main/legacy 的功能合同。命名转换是配置兼容性变更，不会自动升级正在运行的科研状态。

## 配置与源码项目

1. 将原包版本、配置与数据目录保留为不可变备份，记录引擎、版本和绝对工作目录。
2. 在独立副本中更新 import、依赖、CLI 命令与环境变量，包括子进程转发变量和示例任务服务。
3. 将预设类型改为 `scienceevolve-agent-config-preset`，并按生成配置与 `scievolve help` 更新 MCP 服务/工具标识及 Skill 路径。
4. 用新 CLI 校验复制后的配置。迁移试验使用独立且显式选定的数据目录。
5. 在隔离项目中验证创建、暂停/恢复、资源和交付，再决定后续迁移。验证前保留原版本与全部副本。

配置试验回退意味着重新选择未修改的原版本、配置和数据目录。本次重构不迁移真实用户数据。实际科研运行产生的修改需另行处理。

## 已有运行状态

旧项目可能包含工作目录、绝对路径、MCP 注册、序列化提示和原生 profile 元数据。只改顶层目录名不能证明新版本可恢复。保留原引擎/版本，通过旧版本导出产物，再新建独立的新版本任务。不要盲目替换凭据、Git 历史、科学输入/结果或运行数据库中的文本。

历史 legacy CLI 默认使用 `~/.scienceevolve/data`，可由 `--data-dir` 或 `SCIENCEEVOLVE_DATA_DIR` 选择；main CLI 要求显式 `--data-dir`，拒绝仅依靠环境变量选择。目录选择不进行状态转换。legacy 已移除，旧数据需使用对应旧版本。

## 历史与上游证据

带日期的验收记录保留原命令、产物名、实际路径和仓库链接。来源补丁及逐文件命名编辑保留原始字节，以便核对上游 hash。这些是逐项检查的历史例外，不是当前安装说明或兼容别名。

固定内核依次经过上游原文、声明的共用修复/测试适配和确定性命名覆盖生成；检查按相反顺序还原。命名模块字节不受 Git 自动换行转换影响。

## 发布前提

包名不代表已拥有 npm 命名空间。命名审计时，公开请求的新 npm 包和两个仓库返回 404；当时无法确认私人可见性及写权限。这是历史观测，发布时应使用实际发布账号重新验证。

SDK 当前保留 `private: true`。发布 npm 前需由获授权的发布流程显式处理。无发布凭据仍可进行本地打包与安装校验。
